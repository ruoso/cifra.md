# Reference corpus

Each entry is a directory with three files:

| File | What it is |
|---|---|
| `input.cifra.md` | A document as someone might write it: uncanonical spacing, mixed conventions, mistakes a reader must survive. |
| `parsed.json` | The document model a conforming reader produces from `input.md`, valid against [`schema/cifra.schema.json`](../schema/cifra.schema.json). Diagnostics included. |
| `canonical.cifra.md` | The canonical text a conforming writer produces from `parsed.json` (spec §8). |

An implementation validates itself by checking, for every entry:

1. `parse(input.cifra.md)` equals `parsed.json`.
2. `write(parsed.json)` equals `canonical.cifra.md`.
3. `parse(canonical.cifra.md)` equals `parsed.json` with its `diagnostics` emptied of
   anything the canonical form drops, and `write` of that is `canonical.md`
   again: the canonical form is a fixed point.

JSON comparison is structural: key order does not matter, and nothing else
is normalised. The reference implementation's own check is
`reference/tests/test_corpus.py`.

The files `parsed.json` and `canonical.cifra.md` are generated by the
reference implementation from `input.cifra.md`, then reviewed. To add an
entry, write its `input.cifra.md`, run `python -m tools.corpus --write` in `reference/`, and read
what came out before committing it. `--check` is what the test suite runs.
